# Workouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a workout tracker to the Haltewekker iPhone app. It works out what the user lifts today from his own program (rotation, double progression, ladders, deload, sets per week), logs a matching set with one tap (also from an interactive Live Activity), compares every set with earlier days, and imports his Hevy history.

**Architecture:** Every rule lives in Foundation-only files that the hostless `HaltewekkerTests` bundle compiles directly:
- `WorkoutModel.swift` and `WorkoutFormat.swift`: types, tolerant decoding, copy and typed input.
- `WorkoutProgram.swift`: the library, the ladders and the three routines.
- `WorkoutRules.swift`: rotation, progression, ladders and deload.
- `WorkoutStats.swift`: loads, e1RM, records, sets per week, warm-ups, plates, the index and the chart series.
- `WorkoutSession.swift`: a running workout as a value.
- `WorkoutStore.swift`: JSON files in Application Support, one per month.
- `HevyCSV.swift`: the Hevy import.
- `Shared/WorkoutLiveState.swift`: the Live Activity's content state.

The SwiftUI screens read one `WorkoutStore.shared` and follow the Outfit/Recomp pattern: a tag on the map, a card at the top of "more", a sheet, and a full-screen cover for a running workout. A second Live Activity type, `WorkoutAttributes`, runs beside `TripAttributes`. Its `LiveActivityIntent`s run in the app process through a `WorkoutControl` hook that is registered in `HaltewekkerApp.init`, so no App Group is needed.

**Tech Stack:** Swift 5 language mode (Xcode 26), SwiftUI, iOS 17, Swift Charts, ActivityKit + AppIntents (`LiveActivityIntent`), UserNotifications, XCTest, XcodeGen, GitHub Actions (macos-15).

**Spec:** `docs/superpowers/specs/2026-11-15-workouts-design.md`. It is in Dutch; read it first. Its ⚙︎ calls are approved and binding. The program is in `.superpowers/workouts/program.md` and the Hevy format in `.superpowers/workouts/hevy-summary.md`. Both are git-ignored, so read them but never copy them into the repo.

## Global Constraints

- iOS 17.0, SwiftUI, `SWIFT_VERSION 5.0`. Use APIs newer than iOS 17 only behind `#available`.
- No third-party packages. **No new entitlements**: no HealthKit, no App Groups, no Watch target, no push, no time-sensitive notifications. No new Info.plist keys (`NSSupportsLiveActivities` and `haltewekker://` are already there).
- The trip, alarm and GPS behaviour, the trip Live Activity and the ride and morning screens stay exactly as they are. `haltewekker://workout` is routed by host; every other URL still goes to `trip.music.finish(url)`.
- UI copy is **English**, exercise names too. The user's own notes stay as written (Dutch). Use typographic apostrophes (’), "×" (U+00D7), "–" for ranges and "−" (U+2212) for minus.
- Use the Paper look as in Recomp: `Paper`, `HWFont`, `BoardInk.sans`, `.paperCard()`, `PaperFill`, `.brass(pal, pad:)`, light scheme.
  - There is **one accent colour**: `WorkoutStyle.accent = Paper.green`. It marks everything that is done or starts something (✓, Done, Start, the rest bar, "New best"). It is the same green (`0x5E9A36`) on dark in the Live Activity.
  - A drop in reps or weight is plain ink, never red.
  - No badges, streaks, confetti, motivational lines or "missed".
- Put `.monospacedDigit()` on every kg, rep, set count and time. Timers use `Text(timerInterval:)`.
- Tap targets are ≥ 44 pt. ✓ and the bottom Done button are ≥ 56 pt. Animations are ≤ 300 ms and use `.numericText()` for changing numbers.
- Weights are in **kg** only. A dumbbell weight is **per hand**.
- These files import only `Foundation` (`WorkoutStore.swift` also `Combine`):
  - `WorkoutModel.swift`, `WorkoutFormat.swift`, `WorkoutProgram.swift`, `WorkoutRules.swift`, `WorkoutStats.swift`, `WorkoutSession.swift`, `WorkoutStore.swift`, `HevyCSV.swift`;
  - `Shared/WorkoutLiveState.swift`.

  They may use the Recomp pure types that the test target already compiles (`DayKey`, `RecompCalendar`, `RecompInput`, `Measure`, `WeightMath`). They never use `Paper`, `Fmt`, `HWFont`, `RecompStore` or UIKit.
- The task that creates one of those files appends it to `HaltewekkerTests` → `sources:` in `ios/project.yml`. Keep every entry that is already there (Recomp, and Reliability's `Net`, `Memo`, `Snapshots`, `Geo`, `VehicleMatch` and `FieldLog`).
- A workout "day" is `RecompCalendar.day(for: start)`, which runs 04:00 to 04:00 local time. Its month file is the first 7 characters of that day key.
- Storage goes in `Application Support/Workouts/`:
  - the files are `library.json`, `routines.json`, `state.json`, `current.json`, `index.json` and `history/yyyy-MM.json`;
  - each file carries a `version` (1), and every field decodes with `decodeIfPresent` and a default;
  - writes are atomic, with `.completeFileProtectionUntilFirstUserAuthentication`;
  - a file that doesn't decode is renamed to `<stem>.corrupt-<yyyyMMdd-HHmmss>.json`, never overwritten or deleted.
- Tests never use the real Application Support folder, the real clock, the network or the user's real CSV. They inject a temporary directory, a movable clock and the synthetic fixture written in the test source.
- **No local Swift toolchain.**
  - Each task writes its tests and code together and verifies them with one push to `claude/cool-mendel-odsmk9`. In the "Build iPhone app" run, expect `** TEST SUCCEEDED **` and `BUILD SUCCEEDED`, and no release: releases come only from `main`. Read the run with the GitHub MCP tools `actions_list` and `get_job_logs`.
  - Other agents commit in `ios/`, so run `git pull --rebase origin claude/cool-mendel-odsmk9` before every push.
- This plan runs after the Reliability plan (0.18.0 / 83). Line numbers are at HEAD 88f24ab and will have moved, so find each spot by the function or view named. Don't touch `relay/` or `.github/`.
- Commit messages start with "Workouts: ".

## Review Focus

1. **A workout that starts or runs after midnight** (00:30 on 1 Dec) belongs to the day before. That counts for the rotation, the rest day, the month file and the 21-day window, as everywhere else in the app with the 04:00 day. Tests in Task 1 (`test_dayAndMonth`) and Task 3 (`test_afterMidnight`).
2. **A Hevy CSV that was opened and saved again** (CRLF line endings, a UTF-8 BOM) reads to exactly the same rows. Test in Task 7 (`test_crlfAndBom`).
3. **A custom exercise with a very long or emoji-heavy name** must not push the Live Activity over 4 KB. Every text in the state is cut to 40 characters. Test in Task 5 (`test_liveStateStaysSmall`).
4. **"Set done" on a stale Live Activity**, after the last set or after Finish, logs nothing and doesn't crash. Tests in Task 5 (`test_nextNilWhenAllDone`) and Task 6 (`test_completeNextNothingLeft`).
5. **Deleting or editing an old workout** that held a record or the "last time" recomputes both: records and previous values never point at a workout that is gone. Test in Task 6 (`test_deleteRebuildsRecords`).

  ```swift
  enum Muscle: String, Codable, CaseIterable, Sendable {
      case sideDelts, lats, chest, rearDelts, triceps, biceps, frontDelts, core, forearms, traps
      case quads, hamstrings, glutes, calves, adductors, abductors
      var isLeg: Bool { get }          // quads…abductors
      var title: String { get }        // "Side delts", "Lats & back", "Chest", "Rear delts", "Triceps", "Biceps", "Front delts", "Core", "Forearms", "Traps", "Quads", "Hamstrings", "Glutes", "Calves", "Adductors", "Abductors"
  }
  enum SetRow: Hashable, Sendable {
      case muscle(Muscle), legs                                    // legs = every leg muscle together
      static let main: [SetRow]    // sideDelts, lats, chest, rearDelts, triceps, biceps, legs
      static let more: [SetRow]    // frontDelts, core, forearms, traps, quads, hamstrings, glutes, calves, adductors, abductors
      func contains(_ m: Muscle) -> Bool
      var title: String { get }    // legs → "Legs", else the muscle's title
  }
  enum Equipment: String, Codable, CaseIterable { case dumbbell, barbell, cable, machine, smith, bodyweight, other }
  enum ExerciseKind: String, Codable, CaseIterable { case weight, bodyweight, weighted, assisted, time, cardio }
      // weighted: kg is extra weight; assisted: kg is the help; time: seconds; cardio: seconds + km (import only)
  enum SetKind: String, Codable, CaseIterable { case warmup, normal, failure, drop }   // an unknown raw value decodes as .normal
  struct Target: Codable, Equatable { var sets: Int; var lo: Int; var hi: Int; var rirLo: Int? = nil; var rirHi: Int? = nil; var rest: Int }  // lo/hi are seconds for .time; rest in seconds; rirLo nil = no RIR
  struct Exercise: Codable, Identifiable, Equatable {
      var id: String; var name: String; var equipment: Equipment = .other; var kind: ExerciseKind = .weight
      var primary: [Muscle] = []; var secondary: [Muscle] = []; var step: Double? = nil    // nil = the equipment default from settings
      var hevyNames: [String] = []; var custom = false
  }
  enum MoveUpRule: String, Codable { case standard, pullUpToWeighted }
  struct LadderStep: Codable, Equatable { var label: String; var exerciseId: String; var target: Target; var note = ""; var moveUp: MoveUpRule = .standard }
  struct Ladder: Codable, Identifiable, Equatable { var id: String; var name: String; var steps: [LadderStep]; var hint: String; var start: Int }
  struct WarmupRamp: Codable, Equatable { var percent: Double; var reps: Int }       // percent 0 = no load
  struct RoutineItem: Codable, Identifiable, Equatable {
      var id = UUID(); var exerciseId: String? = nil; var ladderId: String? = nil   // exactly one of the two
      var target: Target; var note = ""; var alternatives: [String] = []; var superset: Int? = nil
      var optional = false; var skipOnLegDays = false; var warmup: [WarmupRamp] = []
  }
  struct Routine: Codable, Identifiable, Equatable { var id: String; var name: String; var short: String; var items: [RoutineItem] }
  struct LoggedSet: Codable, Identifiable, Equatable {
      var id = UUID(); var kind: SetKind = .normal; var kg: Double? = nil; var reps: Int? = nil; var seconds: Int? = nil
      var km: Double? = nil; var rir: Int? = nil; var done = false; var doneAt: Date? = nil
      var counts: Bool { get }       // done && kind != .warmup
  }
  struct LoggedExercise: Codable, Identifiable, Equatable {
      var id = UUID(); var exerciseId: String; var ladderId: String? = nil; var routineId: String? = nil
      var target: Target? = nil; var superset: Int? = nil; var note = ""; var sets: [LoggedSet] = []
  }
  enum WorkoutSource: String, Codable { case app, hevy }
  struct Workout: Codable, Identifiable, Equatable {
      var id = UUID(); var title: String; var routineIds: [String] = []; var start: Date; var end: Date? = nil
      var note = ""; var bodyWeight: Double? = nil; var deload = false; var source: WorkoutSource = .app
      var hevyKey: String? = nil; var exercises: [LoggedExercise] = []
      var hardSets: Int { get }       // sets that count
      var day: DayKey { get }         // RecompCalendar.day(for: start)
      var month: String { get }       // String(day.prefix(7))
  }
  struct WorkoutSummary: Codable, Equatable, Identifiable {
      var id: UUID; var title: String; var routineIds: [String]; var start: Date; var end: Date?; var day: DayKey
      var hardSets: Int; var source: WorkoutSource; var hevyKey: String?; var deload: Bool; var exerciseIds: [String]
      init(_ w: Workout)
  }
  struct DeloadState: Codable, Equatable { var active = false; var left: [String] = []; var lastDay: DayKey? = nil; var snoozedUntil: DayKey? = nil }
  struct WorkoutSettings: Codable, Equatable {
      static let defaultSteps: [String: Double] = ["dumbbell": 2, "cable": 2.5, "machine": 2.5, "barbell": 2.5, "smith": 2.5, "weighted": 2.5]
      var restSound = true; var keepScreenOn = false; var bodyWeightFromRecomp = true; var fixedBodyWeight: Double? = nil
      var steps: [String: Double] = WorkoutSettings.defaultSteps
  }
  struct WorkoutState: Codable, Equatable {
      var version = 1; var ladderSteps: [String: Int] = [:]; var deload = DeloadState()
      var firstLegsDay: DayKey? = nil; var firstAppDay: DayKey? = nil; var settings = WorkoutSettings()
  }
  struct RestState: Codable, Equatable { var started: Date; var ends: Date }
  struct ClosedItem: Codable, Identifiable, Equatable { var id: UUID; var routineId: String; var exerciseId: String; var target: Target; var reason: String }  // id = the routine item's id
  struct ActiveWorkout: Codable, Equatable {
      var version = 1; var workout: Workout
      var previous: [String: [LoggedSet]] = [:]      // LoggedExercise.id.uuidString → last time's sets
      var closed: [ClosedItem] = []; var rest: RestState? = nil; var focus: UUID? = nil; var lastRecord: String? = nil
  }
  struct MonthFile: Codable { var version = 1; var month: String; var workouts: [Workout] }
  struct LibraryFile: Codable { var version = 1; var exercises: [Exercise]; var ladders: [Ladder] }
  struct RoutinesFile: Codable { var version = 1; var routines: [Routine] }
  ```

  }

### Task 2: The library, the ladders and the three routines

**Files:**
- Create: `ios/App/WorkoutProgram.swift`, `ios/Tests/WorkoutProgramTests.swift`
- Modify: `ios/project.yml` (append `App/WorkoutProgram.swift`)

**Interfaces:**
- Consumes: the model types (Task 1).
- Produces:
  ```swift
  enum WorkoutProgram {
      static let exercises: [Exercise]
      static let ladders: [Ladder]
      static let routines: [Routine]                       // push, pull, legs
      static func slug(_ name: String) -> String           // lowercase; runs of non-alphanumerics → "-", trimmed: "Seated cable row (V-grip)" → "seated-cable-row-v-grip"
      static func exercise(_ id: String, in list: [Exercise]) -> Exercise?
      static func match(hevy title: String, in list: [Exercise]) -> Exercise?   // trimmed, case-insensitive, against hevyNames
  }
  ```

**The library.** Every exercise's `id` is `slug(name)`, and it is matched by the Hevy names after "←".
- **Kind** is `.weight` unless marked otherwise.
- **Equipment** follows the name (DB → dumbbell, cable → cable, machine/Pec deck → machine, Smith → smith, barbell → barbell). Where the name doesn't say:
  - cable: Bayesian curl, the pushdowns, Lat pulldown, Single-arm cable pulldown, Seated cable row;
  - machine: Leg press, Horizontal leg press, Hack squat, both leg curls, Leg extension, Hip abduction/adduction, Calf press, Seated calf raise;
  - dumbbell: Goblet squat, Seated palms-up wrist curl;
  - bodyweight: everything that is bodyweight, weighted, assisted or a hold;
  - other: the rest.
- **Muscles.** The program exercises have exactly the muscles of the spec's table under "Routines": "Telt voor" is primary, and the names in brackets are secondary. "legs" there means:
  - [quads, glutes] for leg presses and squats;
  - [hamstrings, glutes] for RDLs;
  - [hamstrings] for leg curls;
  - [calves] for calf raises.

  Choose the other exercises' muscles sensibly, from `Muscle`.

| Group | Exercises |

  struct Performance: Codable, Equatable { var workoutId: UUID; var start: Date; var sets: [LoggedSet] }    // the done sets
  struct ExerciseIndex: Codable, Equatable {
      var last: Performance? = nil; var lastByRoutine: [String: Performance] = [:]
      var recent: [SessionBest] = []          // newest last, at most 3, deload workouts left out
      var records = Records(); var sessions = 0
  }
  struct WorkoutIndex: Codable, Equatable {
      var version = 1; var exercises: [String: ExerciseIndex] = [:]; var workouts: [WorkoutSummary] = []   // oldest first
      static func build(_ workouts: [Workout], library: [Exercise]) -> WorkoutIndex
      mutating func add(_ w: Workout, library: [Exercise])     // the same result as build, for a workout newer than all others
  }
  enum Previous {
      static func sets(_ e: ExerciseIndex?, routineId: String?) -> [LoggedSet]   // the same routine first, else the last time anywhere
      static func row(_ previous: [LoggedSet], warmup: Bool, number: Int) -> LoggedSet?   // the number-th (0-based) warm-up or work set
  }
  struct RowCount: Equatable { var direct: Double; var indirect: Double }        // per week
  enum WeeklySets {
      static let priority: Set<SetRow> = [.muscle(.sideDelts), .muscle(.lats)]
      static let floor = 12
      static func count(_ workouts: [Workout], library: [Exercise], today: DayKey, days: Int = 21) -> [SetRow: RowCount]
      static func targets(_ routines: [Routine], ladders: [Ladder], state: WorkoutState, library: [Exercise]) -> [SetRow: Int]
  }
  enum Warmup { static func sets(_ ramps: [WarmupRamp], workKg: Double?, step: Double) -> [LoggedSet] }
  enum Plates { static let bar = 20.0; static let sizes: [Double] = [25, 20, 15, 10, 5, 2.5, 1.25]; static func text(_ total: Double) -> String? }
  struct ExerciseSession: Equatable { var start: Date; var sets: [LoggedSet]; var bodyWeight: Double? }
  enum ChartMetric: String, CaseIterable { case bestSet, e1rm, volume, reps }      // titles "Best set", "e1RM", "Volume", "Reps"
  enum ChartPeriod: String, CaseIterable { case threeMonths, year, all }          // "3 months", "1 year", "All"
  struct ChartPoint: Equatable, Identifiable { var date: Date; var value: Double; var id: Date { date } }
  enum Series {
      static func sessions(_ workouts: [Workout], exerciseId: String) -> [ExerciseSession]   // oldest first; only sessions with a counting set
      static func points(_ s: [ExerciseSession], kind: ExerciseKind, metric: ChartMetric, period: ChartPeriod, now: Date) -> [ChartPoint]
  }

- [ ] **Step 2: Implement `WorkoutStats.swift`.**
  - **Weekly sets.**
    - `count`: the workouts whose `day` is in `[today − (days − 1), today]`.
    - For every counting set and every row in `main + more`: a primary muscle in the row → direct + 1; else a secondary in it → indirect + 0.5.
    - Divide by `days / 7`. Unknown exercise ids are skipped.
  - **Targets.**
    - Weight per routine: 1 for `push` and `pull`, 0.5 for `legs`, 0 for the rest.
    - Per row: Σ over items (optional and leg-day-skipped ones included) of their sets, where a primary muscle is in the row. A ladder item uses its current step's exercise and sets.
    - Then × weight × 7 / 3, `.rounded()`. Rows that come to 0 are left out.
  - **Warm-ups.** `kg = max(step, floor(workKg × p / step) × step)`, or nil when `p == 0` or `workKg == nil`. `kind = .warmup`, `done = false`.
  - **Plates.** Per side `(total − 20) / 2`, filled greedily from `sizes`. One plate size is written "2 × 15"; several are "2 × (25 + 15)". A remainder that won't fit gives nil.
  - **Index.**
    - Every exercise's `routineId` keys `lastByRoutine`.
    - `recent` takes `Lifts.sessionBest` with the workout's `bodyWeight`, skips deload workouts and keeps the last 3.
    - Records add every counting set.
    - `workouts` holds the `WorkoutSummary`s sorted by `start`.
